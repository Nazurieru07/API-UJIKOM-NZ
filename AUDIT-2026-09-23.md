## BUG / INKONSISTENSI DATA

### A. 6 peminjaman tanpa detail alat (KRITIS untuk laporan)

peminjaman.id: 18, 21, 22, 23, 24, 29 -> LEFT JOIN detail_pinjam = 0 baris.
Pelaporan peminjaman kosong untuk 6 dari 13 transaksi. Fix:
  INSERT INTO detail_pinjam (peminjaman_id, alat_id, jumlah, created_at, updated_at)
  SELECT p.id, <alat_id_dari_log>, 1, NOW(), NOW()
  FROM peminjaman p WHERE p.id IN (18,21,22,23,24,29);
  -- alat_id harus direkonstruksi dari log_aktivitas "stok menjadi" saat
  -- peminjaman dibuat (lihat log id 152,165,174,183,214), atau biarkan
  -- kosong dan tandai sebagai data rusak.

Rekonstruksi (dari log_aktivitas):
  18 -> log 152 Mini PC Intel NUC 11 (alat 3)
  21 -> log 158 Kamera DSLR Canon EOS 3000D (alat 2)
  22 -> log 165 Adapter HDMI to VGA (alat 5)
  23 -> log 174 Tang Crimping (alat 4)
  24 -> log 183 Adapter HDMI to VGA (alat 5)
  29 -> log 214 Router Mikrotik RB941-2nD (alat 1)

### B. jobs + notifications numpuk

jobs: 3, notifications: 73. QUEUE_CONNECTION=database, worker tidak pernah
jalan (sejak audit 09-22 belum dikerjakan). Notifikasi peminjaman/pengem-
balian never delivered. Fix:
  docker exec -d laravel-api php artisan queue:work --tries=3
  docker exec laravel-api php artisan notifications:purge

### C. alat id=7 "Teleporter" data sampah

stok=8, stok_baik=5, status_kondisi="Baik". Kondisi mayoritas 5/8 = Baik,
kalkulasi benar, tapi nama alat "Teleporter" + kategori "Perangkat Masa
Depan" jelas data uji coba, bukan master data asli. Kalau demo/ujikom
butuh data bersih, hapus alat 7 + 6 peminjaman yang pakai dia.
